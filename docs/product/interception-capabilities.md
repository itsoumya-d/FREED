Apple's URL filter uses PIR, Privacy Pass and an OHTTP gateway, with Apple distribution approval. It does not run the app/extension when deciding a request, and custom stacks must participate themselves. It therefore supplies neither guaranteed every-browser coverage nor automatic FREED entry. No paid infrastructure was provisioned. [Apple WWDC25](https://developer.apple.com/videos/play/wwdc2025/234/)

Safari permits a `main_frame` redirect to an `extensionPath` with `declarativeNetRequestWithHostAccess` and host access; that stays inside Safari. [Apple WWDC26](https://developer.apple.com/videos/play/wwdc2026/216/)

The installed SDK declares `ShieldActionResponse.openParentalControlsApp` on iOS 26.5+. The current `ShieldActionExtension` publishes its scoped intervention only for the primary button before requesting app opening. This tapped native-app route cannot substitute for browser-wide automatic entry. [Apple API](https://developer.apple.com/documentation/managedsettings/shieldactionresponse/openparentalcontrolsapp)

Android restricts background activity launches, including from foreground services. `FreedVpnService` uses a private notification's `PendingIntent`; an intent ready to open an activity is not proof it opened automatically. Accessibility selected-app behavior needs its own policy/device evidence. [Android activity security](https://developer.android.com/guide/components/activities/secure-bal)

The classic iOS filter deployment limits remain separate from the consumer URL Filter API. Supervised/under-18 child deployment cannot be substituted for FREED's 18+ audience. [Apple TN3134](https://developer.apple.com/documentation/technotes/tn3134-network-extension-provider-deployment)

The newly installed case applies to identified new browsers; all inventoried browsers need the other cases. Each case independently proves blocking, detection, foreground FREED opening, automatic entry and pre-content ordering. Version 1 requires captures within seven days of the verifier clock.

The helper validates descriptors and matching metadata; it does **not** attest arbitrary JSON, read or authenticate artifact contents, or validate store approvals. Device recordings cannot override a narrower public API contract.
