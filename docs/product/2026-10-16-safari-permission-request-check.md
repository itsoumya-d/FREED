# Safari grant shortcut check — 16 October 2026

Primary-source desk research only; no permission, manifest, source code, OS setting or device was changed.

[Apple's permission guide](https://developer.apple.com/documentation/safariservices/managing-safari-web-extension-permissions) distinguishes MV3 host declarations and optional permissions, and describes the user granting access through Safari's extension entry or Settings. Its documented iOS flow supplies no containing-app auto-grant. The official Markdown representation was read after the web reader could not render its content type. This is a documentation fetch, not browser UI execution.

[Mozilla's permissions.request reference](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/permissions/request) requires a user action and describes requests for permissions declared optional. That reference alone does not establish a one-button Safari request for FREED's existing required host inventory. Adding optional scope or claiming request behavior would require its own exact manifest/API review and device evidence.

Accordingly, no automatic permission request or new manifest permission is approved by this check. Current96B uses the supported settings handoff, concise Safari extension guidance and independent observed-result refresh. The actual popup/permission behavior remains unexecuted. A user action in Safari is part of setup; a resolved Settings navigation cannot stand for permission or a configuration check. This does not change the source or declared recovery coverage.
