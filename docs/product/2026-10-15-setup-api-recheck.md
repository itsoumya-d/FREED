# Supported setup routes and rejected DNS shortcut — 15 October 2026

Read-only check against the installed iPhoneOS26.5 headers, current native source and primary Apple documentation. No provider/entitlement, project, console, DNS service, device setting or working protection was changed. This refines the implementation boundaries; it is not a browser/device pass.

- **Safari extension details:** Apple's foreground API opens the specified extension's settings pane; the installed header makes this method available fromiOS26.2. Current `openSafariExtensionSettingsRoute` already calls it with the Focus Shield identifier separately from the content blocker, with an accurately labeled fallback on older versions. This reduces navigation, but does not enable the extension or grant website permission on the user's behalf. [Apple API](https://developer.apple.com/documentation/safariservices/sfsafarisettings/openextensionssettings%28foridentifiers%3Acompletionhandler%3A%29)
- **DNS selection:** installed `NEDNSSettingsManager.h` declares `enabled` read-only and requires the user to enable DNS settings in Settings. Saving is distinct from system selection. Keep the one-current-task instructions and readback; a generic application-settings link is not a DNS deep link. [Apple DNS settings manager](https://developer.apple.com/documentation/networkextension/nednssettingsmanager)
- **Local packet-tunnel substitute:** no packet-tunnel provider was found in the current inspected source. Apple explicitly lists whole-system DNS interception and network content filtering as unsupported uses of a packet tunnel provider. Its expected design forwards packets through a real remote tunnel, so a local DNS-only pseudo-VPN is not an eligible shortcut around the existing architecture. No such target or entitlement was added. [Apple TN3120](https://developer.apple.com/documentation/technotes/tn3120-expected-use-cases-for-network-extension-packet-tunnel-providers)
- **DNS proxy restriction:** Apple's deployment table limits iOS DNS proxies to supervised or per-app managed-device configurations. That cannot be assumed for FREED's ordinary adult customers. [Apple TN3134](https://developer.apple.com/documentation/technotes/tn3134-network-extension-provider-deployment)

The approved minimum remains Safari/iOS recovery and Chrome/Android recovery plus both complete app-limit loops. A Firebase recovery page is a destination; DNS denial is blocking, not an app-opening callback. Guided OS consent, supported extension/barrier/notification entry, correct paid/free access and native expiry must each be demonstrated. The optional hosted DNS pilot still needs its hostname/protocol/cost/consent gates; no paid service was enabled by this check. Keep existing filtering for rollback and never remove it merely to force a redirect demonstration.
