## The primary feasibility gate

| Platform/layer | Blocking | Detect covered attempt | Open FREED | Status |
|---|---|---|---|---|
| iPhone Families DNS | Observed category requests have been blocked | No callback to FREED from the public resolver | No automatic opener | Chrome/all-browser promise blocked |
| iPhone adult Managed Settings policy | System filter configured/read back independently | Does not prove a FREED event for every denied page | No universal automatic-opening contract | Device/browser evidence incomplete |
| iPhone explicitly selected website shields | Opaque native domain selections, up to 50 tokens | Supported shield action path | User action where OS supports it | Must test separately; not arbitrary adult-category coverage |
| Safari extension | Host-permitted main-frame redirect API | Scope of that extension only | Local recovery page → explicit person tap | Default-off private fixture probe added; device test pending |
| Android local VPN | Covered DNS path | Covered local DNS events only | Notification tap is the supported general handoff | Browser bypasses and physical recovery flow pending |

Apple says URL filtering runs without the app executing in the filtering path; alternative networking stacks must participate. Its classic system-wide content-filter providers require supervised iOS devices. A Safari extension cannot operate inside Chrome. DNS cannot replace an HTTPS browser error with our page without breaking TLS. Certificate interception, private APIs, coercive unrelated permissions and supervised/child-only deployment remain excluded. Newly installed browser/proxy/Tor/DoH behavior therefore cannot be claimed universally. The requested public-release gate remains blocked; this is not solved by creating a Cloudflare zone or Worker.

Primary sources checked today: [Apple URL filtering](https://developer.apple.com/videos/play/wwdc2025/234/), [Apple Safari redirects](https://developer.apple.com/videos/play/wwdc2026/216/), [Apple website shields](https://developer.apple.com/documentation/managedsettings/shieldsettings/webdomains-swift.property), [Android launch limits](https://developer.android.com/guide/components/activities/secure-bal), [Cloudflare Families](https://developers.cloudflare.com/1.1.1.1/setup/). [Opal itself documents third-party-browser blocking limitations](https://help.opalapp.com/article/why-isnt-blocking-working-correctly); its marketing is not proof of FREED's universal handoff.
