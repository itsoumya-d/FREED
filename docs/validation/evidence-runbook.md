# FREED Evidence Capture Runbook

Use this runbook to create the six JSON files required by `npm run evidence:validation`. The validator is intentionally strict: do not copy a template into `docs/validation/evidence/` until every placeholder is replaced with real device, store, backend, profiler, log, screenshot, video, or QA-report evidence.

## Preflight

1. Build from the release candidate commit/workspace and record the exact app version/build string.
2. Configure release-mode env vars from `.env.production.example`; do not use sample AdMob IDs, placeholder store-provider keys, local AI endpoints, unsafe enabled weather endpoint/timeout/response-size settings, unsafe remote analytics endpoints, unsafe hosted-backup sync endpoints, unsafe remote retention endpoints, duplicate active env-file keys, malformed non-comment env-file lines, or test-only production flags. For file-based checks, `npm run preflight:release-env -- --env-file <path> --report docs/validation/artifacts/<run-id>/release-env-preflight-report.json` writes a sanitized JSON report for evidence, and `npm run verify:release -- --env-file <path> --artifact-dir docs/validation/artifacts/<run-id>` lets env-file values override stale shell variables while still allowing shell-only secrets to fill omitted keys; the full verifier passes that merged environment to every child command, attaches sanitized report paths to the hosted legal URL audit, upload-signed Android APK/AAB builds, signed iOS Release archive/IPA build, report-capable production preflight/smoke gates, and the final strict release-readiness audit, and rejects missing, malformed, wrong-schema, nonzero-failure, or proof-less reports. These npm scripts preserve app-level `--env-file` arguments with `node --` and fail fast on unsafe `--env-file`, `FREED_RELEASE_ENV_FILE`, `--report`, or `--artifact-dir` values, including URL-shaped, flag-shaped, shell-syntax, template, placeholder, duplicate active env-file keys, malformed non-comment env-file lines, validation evidence/artifact folder, non-`docs/validation/artifacts/<run-id>` report or verifier artifact directories, non-JSON report filenames, missing-value, existing file/symlink artifact path components, or unknown release arguments.
   The full verifier also rejects report artifacts that still contain secret-shaped values such as URL credentials, private keys, OpenAI/Gemini keys, OAuth tokens, JWTs, bearer tokens, FCM server keys, push/device-token shapes, or raw `token=` / `secret=` style parameters, even if their schema and pass counts are valid. Every sanitized report artifact must include a strict ISO UTC `generatedAt` timestamp, and report files checked by `npm run verify:release -- --artifact-dir` must be written during that verifier run; the verifier removes any existing expected report path before launching each report-producing command, so stale files must be recreated by the command under test. The hosted legal URL audit report must prove public HTTPS 2xx HTML for `/privacy`, `/support`, and `/account-deletion`, matching final paths, required legal text, and no `noindex`. The Android APK build report must prove upload signing, Play Console readiness, packaged arm64 ABI, React Native bundle presence, SHA-256, bounded size, and non-debug APK signature verification. The Android AAB build report must prove upload signing, Play Console readiness, `artifactType=aab`, packaged arm64 ABI, React Native bundle presence, SHA-256, and bounded size. The iOS Release archive report must prove App Store Connect export, IPA hash/size, Apple Distribution signing, production bundle IDs, embedded Screen Time/Safari extensions, Family Controls/app-group/Complete Data Protection entitlements, Safari blocker rules, and no packet tunnel/packet inspection entitlements. Deployed smoke reports must include the expected per-smoke result IDs, unique `PASS`/`FAIL` result rows with non-empty details, summary counts that match those rows, required proof values for endpoint paths, privacy/rejection booleans, timeout bounds, private echo-pattern counts where present, and checked secret-key-name arrays, plus the `retention-remote-endpoint` result and retention proof booleans whenever `EXPO_PUBLIC_RETENTION_ENDPOINT` is configured.
   Full preflight reports also include `blockerGroups`, a sanitized mapping from individual preflight failures to the release blocker groups they keep blocked, including required env keys, required follow-up report commands, capture helpers, and target evidence files. Unsafe argument/env-file parse failures intentionally stop before printing production blocker triage. The final verifier requires this array on sanitized preflight report artifacts and rejects inconsistent group status, missing required reports, missing preflight IDs, wrong-group failed checks, or pass/fail counts that do not match the checks.
   The final `audit:release:strict` report must also be strict, warning-free, count-consistent, and include the full release-readiness gate set as passing. The release audit self-checks that the verifier's expected gate manifest exactly matches the audit gate order.
3. Create an artifact directory for the run, for example `docs/validation/artifacts/2026-05-12-ios-physical-device/`.
4. Run `npm run evidence:scaffold -- --run-id <date-or-qa-run>` to copy template drafts, requirements, and the generated `CAPTURE_PLAN.md` checklist into that artifact area, or start manually from the matching file in `docs/validation/templates/`.
   Do not scaffold drafts inside `docs/validation/evidence/`; the scaffold command refuses the release-gated directory so placeholders cannot accidentally become release evidence.
   Evidence capture helper `--output-dir` values are also guarded and must stay under `docs/validation/artifacts/<run-id>/...`, not `docs/validation/evidence/`, outside-workspace paths, random workspace folders, URLs, flags, shell-syntax paths, or placeholders.
   The generated `requirements.json` also includes a schema version, `generatedAt`, `productionEnvChecklist`, `handoffDocuments`, `handoffDocumentCommands`, and `productionBlockerGroups`, a machine-readable grouping of remaining release gates with required env keys, sanitized report commands, capture helper commands, and target evidence files. The production env checklist carries the same private evidence warning as generated draft packages: Do not put App Store private keys, Play service accounts, Supabase service-role keys, Redis tokens, push credentials, maintenance secrets, access tokens, purchase receipts, raw purchase tokens, or AI provider keys in any evidence JSON.
5. Keep the working copy outside `docs/validation/evidence/` until the run is complete.
6. Run `npm run evidence:requirements` if you need a machine-readable list of handoff docs, canonical capture/report/validation/promotion commands, production blocker groups, required target files, check names, and numeric profile fields.
7. Use a concrete UTC ISO timestamp for `validatedAt`, for example `2026-05-12T09:00:00.000Z`; date-only values are rejected, and future values are rejected.
8. Store videos, screenshots, profiler exports, policy-review tickets, command logs, and QA reports in `docs/validation/artifacts/` or use a real HTTPS QA/report URL.
9. Run `npm run evidence:validation:draft -- docs/validation/artifacts/<run-id>/draft-evidence` while the evidence is still in the draft package.
10. Promote the completed JSON files with `npm run evidence:promote -- --from docs/validation/artifacts/<run-id>/draft-evidence`; this validates again and refuses partial promotion. The promotion command refuses `docs/validation/evidence/` as a draft source.
11. Run `npm run evidence:validation` after promotion.

Evidence references must be unique existing non-empty files under `docs/validation/artifacts/` or HTTPS URLs with non-local, non-private, non-placeholder hosts. Remote URLs must point to a QA/report/artifact-style path; generic public webpages are rejected. Remote evidence hosts are checked with the same production endpoint safety rules, including rejection of `.internal`, `.localhost`, private/reserved IP ranges such as `198.18.0.0/15`, and placeholder host text such as `your-*`, `sample`, or `todo`. Replace angle-bracket placeholders such as `<production-env-file>` with the real command path or omit the env-file suffix; literal angle-bracket placeholders are rejected, as are template env files such as `.env.production.example` or `.env.example`. Evidence command fields that include `-- --env-file` must use a local env-file path such as `.env.production` or `secrets/prod.env`; URLs, extra flags, shell syntax, and validation evidence/artifact folders are rejected. Run, report, review, and ticket fields must use concrete machine-readable IDs such as `ios-normal-browsing-release-run` or `ai-safety-eval-2026-05-12`; prose values, whitespace, single words like `run`/`report`/`review`, template-ish `example`/`placeholder` values, and duplicate proof IDs within the same evidence file are rejected.
The evidence scaffold, draft validator, and promotion CLIs fail on unknown flags or missing option values before reading or writing evidence, so re-run the command instead of relying on default paths if a handoff command was mistyped.

## iOS Physical Device

Target file: `docs/validation/evidence/ios-physical-device.json`

Run on a physical iPhone signed with Apple-approved Family Controls and the `group.app.freed.recovery` app group. Use `docs/store-policy/ios-screen-time-safari-dns-review.md` as the source copy for App Store review notes covering Screen Time, Safari Content Blocker, Safari Focus Shield, and iOS platform boundaries.

