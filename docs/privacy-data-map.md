## Store Review Notes

- Store privacy answer sheets live in `store/play-store/data-safety.md` and `store/app-store/app-privacy.md`; cross-check both against this data map, `store/privacy-policy.md`, the enabled production env, and the platform policy packs before entering Play Console or App Store Connect answers.
- Current iOS `PrivacyInfo.xcprivacy` declares no tracking and no collected data types for the local-first build.
- Current iOS app and extension entitlements set `com.apple.developer.default-data-protection` to `NSFileProtectionComplete`, so local recovery state and app-group Screen Time/Safari handoff files default to Complete Data Protection.
- Current Android source and generated release manifests do not request advertising ID permission, overlay permission, microphone access, or media-library/storage access. Challenge photo verification uses fresh camera capture only, requests no base64 or EXIF payload, deletes the temporary camera file on a best-effort basis after on-device classification, and the Expo config plus source manifest block microphone, legacy storage, Android 13+ media image/video/audio, selected-media, media-location, and all-files storage permissions from library merges.
- Current Android manifest disables implicit OS backup and device-transfer extraction for local recovery data. FREED recovery continuity must use the explicit encrypted backup flow, where the user chooses a passphrase and hosted sync stores only encrypted envelopes.
- iOS Screen Time, Safari Content Blocker, Safari Focus Shield, and challenge-verification App Store review copy lives in `docs/store-policy/ios-screen-time-safari-dns-review.md`; it documents opaque Screen Time tokens, no third-party app screen reading, no native Reels/Shorts/TikTok in-app detection, no Safari browsing-history collection, no screenshot/OCR/continuous image analysis, no packet tunnel/full VPN, and no challenge media upload in the current local-first build.
- Protection setup explains Screen Time, Safari extensions, Android DNS-only VPN, Accessibility, notifications, and challenge-verification permissions separately, documents that camera, iOS motion/pedometer, Android Activity Recognition/steps, and foreground location are requested only on demand for challenge verification, runs the activation test without adding fake blocked-attempt history, and keeps native iOS/Android setup gated until activation is complete.
- Android AccessibilityService and DNS Guard foreground-service Play review copy lives in `docs/store-policy/android-accessibility-and-fgs-disclosure.md`; it documents explicit opt-in, no screenshots/OCR/page-text scraping, no raw URL path/query persistence, no full traffic proxying, no MITM HTTPS, no sale/sharing of AccessibilityService data, and the required Play policy review artifacts.
- Production store billing, optional RevenueCat fallback, AdMob, enabled third-party weather context, enabled remote analytics, enabled hosted backup sync, or remote community features must update App Store/Play Store privacy disclosures before release.
- Raw browsing URLs should remain out of persisted state and AI requests unless a future debugging tool asks for explicit, revocable user consent.
