# Firebase demo emulator verification

Use Node 22, matching `functions/package.json` and `firebase.json`. Put that runtime first on `PATH` so the Firebase CLI, function discovery worker, and test subprocess also use it. Run one verification process at a time on the shared Mac.

```sh
node --test --test-concurrency=1 tests/feature-emulator-startup.test.js tests/feature-test-manifest.test.js
node scripts/run-feature-verification.js --mode emulator \
  --report docs/validation/artifacts/2026-10-03-premium-emulator/emulator.json
```

The canonical runner builds Functions and runs the complete compiled Functions suite with one test worker inside Auth, Firestore, Storage, and Functions emulators. It binds `--project demo-freed-feature-verification` explicitly; `.firebaserc`'s production default does not select this run. Java is limited to 384 MB and Node children to 512 MB. It does not deploy, control native simulators, send live mail or messages, or perform store purchases.

## Public parameter startup

Firebase CLI 14.7.0 asks for unresolved `defineString` parameters during Functions discovery, including parameters with source defaults. Its emulator discovery passes `nonInteractive: false` internally, so adding only `--non-interactive` does not resolve the prompt. The earlier [emulator run](../validation/artifacts/2026-10-02-feature-coverage/2026-10-02T13-02-16-840Z/emulator.json) timed out before the test command started.

The runner now creates `functions/.env.demo-freed-feature-verification` with an exclusive write only when the file is absent:

```dotenv
# Public parameter for the disposable Firebase demo project only.
GOOGLE_PLAY_SUBSCRIPTION_TOPIC=freed-feature-verification-google-play-subscriptions
```

This value names a public test topic; it is not a store credential or API key. The fixture is covered by the repository's `.env.*` ignore rule and can be regenerated by the runner. Existing fixture bytes are preserved. An existing fixture missing the exact single public parameter fails promptly with a repair message. `.env.local` and `.secret.local` are never created or overwritten by this preparation step. Do not copy production keys into this fixture. Adding new non-secret Functions parameters requires extending the demo fixture and startup regression deliberately.

The startup regression uses the installed Firebase CLI's dotenv loader and parameter resolver, verifies resolution without prompting, and checks preservation of existing configuration. The runner also passes `--non-interactive` and explicit demo project environment values.

## Unit execution

The Functions tests read source and certificate fixtures relative to `functions`, so run them from that directory. For a memory-bounded unit run:

```sh
npm --prefix functions run build
cd functions
GCLOUD_PROJECT=demo-freed-feature-verification \
GOOGLE_CLOUD_PROJECT=demo-freed-feature-verification \
node --test --test-concurrency=1 lib/*.test.js
```

Five cases require emulators and are skipped in unit-only execution. The canonical emulator run must execute them rather than treating the unit skip as proof.

## Evidence limits

The actual run is recorded under [2026-10-03-premium-emulator](../validation/artifacts/2026-10-03-premium-emulator/README.md), including raw test output sanitized for local paths, log hashes, source snapshots, and startup red/green evidence. The report preserves all 106 catalog features: 99 historical ledger rows plus seven appended premium obligations.

A passing Functions suite supplies backend isolation evidence. It does not supply the feature-specific execution receipts required by the manifest. Without those receipts, the canonical report remains incomplete and exits `2`; `--allow-incomplete` changes only that exit policy. Native UI, real store sandbox, live deployment, physical-device enforcement, accessibility, and measured motion requirements remain separate.

Pub/Sub is outside this runner's emulator selection. The CLI initializes HTTP function definitions but ignores the Google subscription notification trigger and scheduled jobs. The suite tests injected notification/store processors and directly invokes deletion handlers against actual emulated data services; it does not establish Pub/Sub delivery, callable HTTP transport, a live provider, or a deployed schedule.

The Storage emulator does not fully implement production GCS generation preconditions. Read its diagnostic output before interpreting the passing adapter test; production stale-write rejection still needs its own integration evidence.
