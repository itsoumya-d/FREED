## Load-bearing findings

1. **P1 — Haptic preference changes silently stop a running breathing session.** FunctionalBreathingScreen.tsx:37–42 recreates the timer effect when `hapticCues` changes. Its cleanup calls `session.pause`, but its replacement only installs ticks/checkpoints, never resumes the clock while `running` remains true. The UI continues to say the session is running while cadence and active duration are frozen. The session model reproduces the exact lifecycle: resume at0, cleanup pause at1000, replacement checkpoint at2000, elapsed at6000 remains1000 instead of6000. Keep the haptic setting in a ref/separate effect or resume the active clock when reinstalling a legitimately running lifecycle effect. Add an integrated start → toggle haptics → continue → finish test; the pure session tests alone do not exercise this React cleanup.

2. **P1 — Android history date picker does not dismiss its native dialog.** RecoveryHistory.tsx:51 mounts `DateTimePicker` without `presentation="inline"` and without an `onDismiss`/selection handler that unmounts it. Expo UI's Android adapter defaults to dialog. Its installed Kotlin DatePickerDialog confirms by emitting `onDateSelected`; it does not hide itself. Current onChange only updates `pickerDate`, leaving the native dialog mounted above the outer sheet's “View this day” button; dismissal likewise leaves it mounted. Use inline native presentation inside the existing sheet, or handle the dialog selection/cancel by unmounting the picker. Verify Android confirm and cancel, not only the mocked picker boundary.

3. **P1 — Breathing completion is dated at Save instead of Finish.** FunctionalBreathingScreen.tsx:55 stores only seconds when Finish is pressed; lines57–58 recompute `dateKey` from the current wall clock on Save. Finish just before midnight and save the outcome after midnight silently assigns yesterday's observed activity to today. The data writer's stale-date guard cannot detect this because the UI has replaced the original date. Capture a pending receipt's finish date when Finish is pressed, retain it through retries/resume, and show explicit stale-result handling rather than silently retargeting the activity. This is the pending-receipt/date-at-finish boundary required in the earlier integration instruction.

4. **P1 — An open plan editor silently moves yesterday's edits to today after midnight.** MomentumToday.tsx:39,62,68 keeps `selection` while the parent's Today clock advances. FunctionalToday.tsx:23,34 recreates onPlanChange with the new dateKey. The modal never captures the date on which it opened. Once the clock tick arrives, Save passes its day check and writes the old selection to the new date. Pin an edit date when opening, pass that date to updatePersonalDailyPlan, and close/reopen or explicitly move the choices when the day changes. Exercise an open edited picker across midnight, including foreground refresh.

5. **P1 — Saving a chosen Journal task does not complete that task.** In the initially observed NEW root journal binding, onSave only persisted `recordJournalForDate`. That writer deliberately saves text/purpose, without setting the daily habit. FunctionalToday.tsx:26–30 and MomentumToday.tsx:42–43 use habit.done for the chosen Journal task and next action. Reproduction using the exact binding: after mood+urge check-in and saving words for a journal-only selected plan, journalSaved=true, journalPracticeDone=false and progress stays1/2; the next recommendation remains Journal. Atomically record journal habit completion with the explicit note save, while allowing later undo to retain the note. This was observed before a later root monolith restore; confirm the corrected NEW binding during reapplication.

## Other actionable contract mismatches

6. **P2 — Optional practices cannot all be removed.** MomentumToday.tsx:68 disables Save when `selection.length===0` and requires one or two practices in copy. The approved contract is at most two optional chosen practices, and updatePersonalDailyPlan supports[] for a check-in-only plan. Allow zero choices and verify the resulting1-task denominator on Today and its dated history.

7. **P2 — The next-step CTA does not open the selected boundary/cold-shower task.** FunctionalToday.tsx:28 sends every non-journal/meditation/exercise key to the generic Library. Choosing adult-content boundary, social-media boundary or cold shower therefore yields a “Start practice · [chosen task]” CTA that opens unrelated library navigation, while the correct instructions and self-report are only reachable through the plan row. Route these selected tasks to their own PracticeDetail/self-report surface.

8. **P2 — History hides available targets and archived completion counts.** RecoveryHistory.tsx:43 skips the whole record panel when hasRecordedActivity=false, even if day.plan is an explicitly saved dated plan with zero performed tasks. Its stable targets and0/N count disappear. Separately, line46 tests day.resets>0 but renders only retained resetRecords and never displays the aggregate count or explains pruning. An archived-only day gets an empty “Completed resets” section; a401-reset day can display only200 entries without its real total. Render retained plan targets independently of performed-activity availability, show the known total and explicitly identify unavailable/pruned details.

9. **P2 — Durable save and scratch cleanup failures are conflated.** FunctionalBreathingScreen.tsx:58–60 durably records before calling session.clear. ToolCompletionView.tsx:20 treats any later exception as “could not be saved”; its successful no-help path calls onSkip, which clears the scratch key a second time. If cleanup fails after the durable receipt, the UI states the saved activity was not saved, keeps editable choices, and can restore the already-completed session ID later. The data registry prevents a duplicate reset, but a changed retry practice choice is also ignored by that dedup fence. Keep a committed-result receipt in the UI, acknowledge save separately from cleanup, clear once, and never resume an identity already in the durable tool registry. Leave-without-recording should also handle a cleanup failure without an uncaught press error.

## Confirmed boundaries

- Today and Progress derive their normal date-local counts from the snapshot/dated plan; historical target denominators are nullable when not retained. All six self-report practices remain available outside the chosen subset.
- JournalScreen pins its draft date, disables stale saves and offers explicit “Use draft today”; its writer preserves prior answers and purpose, and unchecking a habit does not delete the note.
- The actual current tool writer has session-identity dedup, keeps observed duration, requires an explicit practice choice, defaults helpfulness to unknown and grants no native event/unlock/protection timestamp.
- Breathing session restoration is paused; pause/background time does not accrue; checkpoints preserve observed time. Mode changes intentionally reset into a new paused identity; existing pure tests cover this behavior.
- Root persistence is synchronous and commits storage before published state, so the current synchronous save handlers can catch a durable write failure.
