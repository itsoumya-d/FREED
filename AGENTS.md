# FREED agent instructions

Read [agent.md](agent.md) before planning or changing this product. The current release contract was approved on 2026-10-13; it retains the earned-time policy approved on 2026-10-08.

## Working rules

- Preserve the shared, uncommitted workspace and the approved home, kite identity, restored paywall, light/dark themes, and ten languages. Do not reset, clean, stash, or revert another contributor's work.
- Keep Expo 55 and React Native 0.83.6. Use only the existing iPhone 16 Plus simulator for layout checks. Install no additional simulator/runtime. Do not request Mirroring again under the current user preference; use structured user testing for phone-only checks, or Mirroring when the user offers it.
- Assign bounded file/function ownership when delegating. Writers are not alone in this checkout. Use one native compiler/build at a time on this Mac.
- Verify actual controllers/native adapters and their failure paths. Retain existing assertions unless the approved behavior changes; explain the change and retain its evidence.
- For mobile UI work, use the global `mobbin-mobile-design` skill and connected Mobbin references. Preserve the theme; reduce duplicate prose with recognizable controls and progressive disclosure while retaining essential requirements, consent and failure information. Record inspected images separately from unreviewed screens and device evidence.
- Keep credentials server-side and outside the repository. Photo verification and challenge selection stay local. Do not send browsing context, journal text, photos, or native Screen Time data to advertising services.

## Product and release rules

- The product is the complete interruption-to-recovery journey defined in agent.md. DNS configuration, a successful build, source tests, screenshots, or a redesigned screen alone are not completion.
- Treat blocking, detecting an attempt, opening FREED, guided access, challenge completion, and native expiry as separate capabilities with separate evidence.
- Version 3, approved on 13 October, permits shipping verified coverage on both platforms. The first release requires Safari/iOS recovery, Chrome/Android recovery, and complete app-limit journeys on both. List other browser/platform paths as verified recovery, blocking only, unsupported or untested; never infer one browser's result from another. Automatic entry or one clear Open Challenge action is accepted. A plain browser error or manual app-icon opening is insufficient.
- Each advertised path must be supported by public APIs, eligible under store policy and demonstrated on its declared devices/conditions. Preserve historical version-1/version-2 universal requirements and failures without promoting them. Universal claims remain prohibited until separately proved; unverified optional browsers no longer block otherwise verified version-3 coverage.
- Ads require an explicit foreground choice and genuine SDK reward evidence. Internal video tests use Google test mode and `networkExtras: { ft_ctype: "video_app_install" }`; this parameter must not leak into production requests or be represented as delivered video without device evidence. Premium users receive guided access without ads. Unknown membership never triggers an ad. Basic help and SOS stay ad-free.
- Ads and challenges never unlock adult websites. Version 2 app breaks are explicitly requested 5-/10-/20-minute windows (20 added on 11 October) for only the originating app, with a default 20-minute daily extra-time cap per rule. Preserve immutable v1 lease semantics. Native scope, cap consumption, exact retries and expiry must work without keeping FREED open.
- History restoration never restores native unlock authority. Account changes must not transfer another owner's private history, purchase ownership, or intervention authority.
- Bind evidence to source snapshot, binary, device/OS, scenario, outcome, and artifact. Record failed, unavailable, and unexecuted checks. Never turn source coverage into a phone-enforcement or launch-readiness claim.

## Documentation

Keep the product capability assessment and delivery ledger current. Preserve prior evidence packets; supersede inaccurate conclusions with a dated correction rather than rewriting history. Do not provision paid services or change security-sensitive console access merely to make a check pass.
