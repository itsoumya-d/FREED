# FREED Full-Feature Audit & Completion Plan

## Context (from discovery)
FREED is an Expo/React Native TypeScript app — **not** SwiftUI/Compose. One shared UI file (`src/features/freed-app.tsx`, 8,546 lines), one custom native module (`modules/freed-protection`: Swift + Kotlin for VPN/DNS blocking, accessibility, usage access), Firebase Cloud Functions backend, and web routes for legal pages. The app's business logic (blocking, purchases, CLARA AI coach, challenges, recovery tracking, notifications, encrypted backup, analytics) is wired end-to-end with no code stubs. The gaps are in UI/interaction/motion quality. Per user decisions: use **react-native-reanimated**, **wire dead UI to real behavior**, and use **real AdMob test units** (Google sample IDs) with TODO markers for release-time swap.

## Phase 2 — Gap fixes (implementation order)

### 1. Foundation
- Add `react-native-reanimated` + `expo-haptics`; run prebuild so native module links. Verify Android `windowSoftInputMode` (resize) for keyboard parity.
- Create a small motion module in `src/design-system/` (transitions presets, spring configs, `FadeInView`, `ScreenTransition` wrapper) so motion tokens live next to the existing theme.

### 2. Rewarded ad screen — real test ads (explicitly NO production ad units)
- Implement full state machine in `RewardedAdScreen`: load → show → reward → error, with visible loading, error + retry, and skip handling.
- Use Google's **sample rewarded unit ID** `ca-app-pub-3940256099942544/1713987310` (and keep existing `EXPO_PUBLIC_ADMOB_USE_TEST_ADS` forcing logic). Add `// TODO(release-ads): swap sample unit IDs for EXPO_PUBLIC_ADMOB_REWARDED_RESET_UNIT_ID_*` markers at the config point. Keep the existing fallback-reset path for when the SDK is unavailable, but surface it as a visible notice instead of a silent substitution.

### 3. Dead UI → real behavior
- Library "Journal" tile → navigate to existing check-in screen; "Move" tile → start a challenge.
- Article cards → in-app reader view (content from `src/data/` or a small local content file) or clearly disabled "coming soon" state; remove fake chevron affordance if not tappable.
- HomeScreen shield/target icon chips → navigate to Shield tab / challenge flow.

### 4. State coverage
- CoachPanel: distinguish network/API error from real replies; show inline error with retry.
- AnalyticsScreen: empty state (icon + title + CTA pattern, reusable component) when no data; skeleton/spinner where computed async.
- Extract a shared `EmptyState` and `InlineNotice` (error/success/info) component; replace stringly-typed `status`/`protectionSyncMessage` mixing of error vs info in ProtectionSetup where cheap to do.

### 5. Motion system
- Breathing circle: continuous animated scale/opacity over the 4-7-8 phases with `withTiming`/`withSpring` and phase-synced text.
- Screen switches in `FreedApp`: wrap each screen render in a keyed fade/slide transition (~200–250ms, eased) so the intercept→ad→challenge chain flows.
- StreakOrb / ProgressRing: animate `strokeDashoffset` and pulse.
- PillButton: springed press scale (replace instant 0.97 jump).
- List/card entry: subtle staggered fade-up for main lists (Library, Today cards).

### 6. Platform parity & accessibility
- Haptics on Android via expo-haptics (selection/impact equivalents).
- Unify back buttons: one accessible 44×44 `BackButton` component with `accessibilityRole="label"` (replace the three divergent implementations in Library/Coach/Breathing).
- Consolidate `LegacyProfileScreen`/`ProfileScreen` duplication if low-risk; otherwise ensure `storageError` surfaces via the new notice system on the main path.

## Verification
- `npx tsc --noEmit`, existing test suites (`npm test` / functions tests), `npx expo prebuild` cleanliness.
- Manual smoke of key flows where simulator permits (onboarding, intercept→ad test ad, challenge, breathing, coach error path).
- Update `docs/completion-audit.md` with the resolved items and the ad TODO markers.

## Out of scope
- Real ad network IDs / production ad units (TODO markers only).
- Native blocking validation on physical devices, live store purchases, live AI keys — existing release gates, unchanged.
- Supabase legacy backend (superseded by Firebase).
